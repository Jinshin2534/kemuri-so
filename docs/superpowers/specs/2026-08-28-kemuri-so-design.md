# けむり相（kemuri-so）設計書

作成日: 2026-08-28

## 1. 概要

顔を撮ると「その人が吸っていそうな銘柄」を確率つきで返すブラウザアプリ。
同時に、その判定が当たるのかを検証するクイズを内蔵する。

- 場所: `ranzo_project/kemuri-so`
- 構成: Vite + 素のJS + Vitest、`pnpm dev` で port 5410
- 推論はすべて端末内（エッジ）で完結。**顔写真はサーバに送らない**（サーバ自体を持たない）
- 掌鑑（手相）・足占（足相）の系譜。人相版にあたる

## 2. 背景：データ事情の調査結果

設計の前提として、2026-08-28 時点で以下を確認した。

- **顔と銘柄を対応づけた公開データセットは存在しない。** 喫煙「行為」を検出する画像データセットや、たばこパッケージの銘柄分類データセットはあるが、いずれも顔とは無関係。
- **年代×性別の喫煙率は公開されている。** 厚生労働省「令和5年 国民健康・栄養調査」（全体15.7%、男性25.6%、女性6.9%、40〜50代男性は3割超）。
  出典: https://www.mhlw.go.jp/content/10900000/001338334.pdf
- **加熱式デバイスの年代別シェアは民間調査にクロス集計がある。** 2026年1月調査、加熱式ユーザー n=4,529、セルフ型ネットアンケート。
  出典: https://relazo.net/tabacco-share/
- **紙巻きたばこの銘柄×年代のクロス集計は公開されていない。** 上記調査も紙巻きは総シェア率のみで銘柄別の内訳を持たない。
- エッジ推論には `@vladmandic/face-api` が使える。1回の推論で **年齢推定・性別・128次元の顔ベクトル（descriptor）** が同時に取れ、すべてブラウザ内で動く。
  出典: https://github.com/vladmandic/face-api
- **モデルの重みは計約7.3MB**（2026-08-28 に実測）。内訳は
  `tiny_face_detector` 192KB / `face_landmark_68` 357KB / `age_gender` 428KB / `face_recognition` **6.3MB**。
  顔ベクトルを作る `face_recognition` が大半を占める。CDN は使わず `public/models/` に自己ホストし、
  **ホーム画面では読み込まず、判定・クイズに入ったときに初めて読み込む**（2回目以降はブラウザキャッシュが効く）。
  読み込み中は進捗を出す。

つまり「顔→銘柄」の直通ルートは作れない。作れるのは「顔→年代・性別→その層の銘柄分布」であり、
顔そのものを効かせるには自前でデータを集めるしかない。

## 3. 方針

### 採用：統計を土台に、集まったデータで上書きしていくベイズ合成

```
P(銘柄 b | 顔) ∝ P(b | 年代, 性別) × L(顔ベクトル | b)^w
                 ~~~~~~~~~~~~~~~~~~   ~~~~~~~~~~~~~~~~~~~~
                 公開統計からの事前分布   自己申告データのkNN尤度
                                        w = n / (n + k)
```

- 登録0件でも統計だけで動く（`w = 0` で事前分布そのもの）
- 登録が増えるほど顔ベクトルが効いてくる（`w → 1`）
- **「登録が増えるとAIが育つ」が実装として本当に起きる**のがこの方式の価値

### 却下した案

- **kNNのみ**: 実装は最小だが、登録が数十件たまるまで何も返せず初回起動が空。上式の `w=1` に相当し、採用案に内包される。
- **統計のみ**: 常に「40代男性ならメビウス」しか言わず、顔を撮る意味がない。上式の `w=0` に相当し、同じく内包される。

## 4. アーキテクチャ


## 5. 推論の詳細

### 5.1 事前分布

`prior(ageBand, gender)` は `stats.js` の以下から合成する。

- 銘柄ごとの全体シェア（実データ）
- 加熱式 / 紙巻きの比率（年代別・実データ）
- 銘柄ごとの年代偏り補正係数（**推定値**。公開クロス集計が存在しないため）

年代帯は 20代 / 30代 / 40代 / 50代 / 60代以上 の5区分。

### 5.2 尤度

登録済みレコード i（顔ベクトル `v_i`、銘柄 `b_i`）に対し、入力ベクトル `v` との距離 `d_i` から

```
score(b) = Σ_{i: b_i = b} exp(-d_i² / (2σ²))
L(b)     = (score(b) + α) / Σ_b' (score(b') + α)      // ラプラス平滑化
```

- 距離 `d_i` はユークリッド距離を使う（face-api の descriptor はこれを前提に学習されている）
- `σ` は距離のスケール定数（face-api の同一人物判定閾値0.6を目安に 0.35 から調整）
- `α` は平滑化定数。登録が偏っていても尤度が0にならないようにする
- 登録0件のとき `L` は一様分布になる（実装として保証し、テストで確認する）

### 5.3 合成と重み

```
posterior(b) ∝ prior(b) × L(b)^w        w = n / (n + k)、k = 20
```

`n` は総登録件数。`k = 20` は「20件たまったら顔と統計が半々」の意図。

### 5.4 判定内訳の算出

事前分布からどれだけ動いたかを total variation distance で測る。

```
faceContribution = Σ_b |posterior(b) - prior(b)| / 2
statsContribution = 1 - faceContribution
```

これを「統計 82% / 顔 18%」として **毎回必ず表示する**。
データが少ないうちは「ほぼ年代と性別で言っています」と自白することになるが、
それが登録を増やす動機になり、クイズを実験として成立させる。

### 5.5 「吸わない」を候補に入れない

喫煙率を事前分布に含めると、ほとんどの層で「吸わない」が最大になり判定が死ぬ。
判定モードは「吸っているとしたら」を前提とし、銘柄マスタに「吸わない」クラスは置かない。
代わりに結果画面の補足として「この層の喫煙率は◯%」を出典つきで添える。

## 6. データモデル

```js
{
  id,                 // uuid
  createdAt,
  label,              // 表示名（端末内のみ）
  brandId,            // 銘柄マスタのID
  face: {
    descriptor,       // number[128]
    age,              // 推定年齢
    gender,           // 'male' | 'female'
    genderProb
  },
  photo,              // dataURL | null。端末内のみ。書き出し時に含める/含めないを選択
  consent             // 本人以外を登録したときの同意チェック
}
```

保存先は IndexedDB（写真を持つため localStorage では容量が足りない）。

書き出し JSON は `{ version, records[] }`。`photo` を落とすと中身は数値の列のみになり、顔には復元できない。
読み込み時は `id` で重複排除する。

## 7. 学習データの集め方

3つの経路を用意する。

1. **自己申告登録** — 顔を撮る → 銘柄を選ぶ → レコードを端末内に保存。写真もクイズ用に端末内だけに残す。
2. **種データ `seed.json`** — 開発時に手持ち写真から作る初期データ。**他人の顔写真そのものは同梱しない**。
   ベクトル化した数値だけを入れる。判定の学習には効くが、写真がないのでクイズには出てこない。
3. **持ち寄りインポート** — 登録を JSON で書き出して合流させる。書き出し時に写真の有無を選べる。

初版ではサーバを作らない。「写真が端末から出ない」という約束を保てるため。
将来の共有サーバは、この JSON をそのまま送る形で後付けできる。

## 8. 画面と導線

```
ホーム ─┬─ 判定する ──→ 撮影/写真選択 ──→ 結果（上位3銘柄＋確率＋効いた内訳）
        │                                      │
        │                                      └─→「実際は？」→ 登録   ★収集エンジン
        ├─ クイズ ────┬─ 銘柄当て（顔→4択）
        │              └─ 逆引き（銘柄→4人の顔）
        │                     └→ 成績：あなた / AI / でたらめ(25%)
        ├─ 登録一覧（端末内・個別削除）
        └─ データ（書き出し・読み込み・統計の出典一覧）
```

判定結果の画面に **必ず「実際は何を吸っているか」を教える導線を置く**。
判定して面白がった直後が、正解ラベルをもらえる唯一のタイミングであり、ここがデータ収集の本体。

初回起動時のみ、20歳以上の確認と免責を表示する。

## 9. 銘柄マスタ

25件前後。カテゴリは以下。

- 紙巻きレギュラー
- 紙巻きメンソール
- 加熱式
- 手巻き（シャグ）
- リトルシガー
- VAPE / 電子

各銘柄は `{ id, name, maker, category, tarLevel, share }` を持つ。

- `tarLevel`: タール量（mg）。加熱式・VAPE は `null`
- `share`: 全喫煙者に占める推定シェア。`stats.js` と同じく `{ value, source, estimated }` の形で持ち、
  出典が取れた銘柄は実データ、取れないものは推定値として明示する。全銘柄の `value` の総和を1に正規化して使う
**ロゴやパッケージ画像は一切使わない。** テキストと色帯のみで表現する。

## 10. クイズ仕様

- **銘柄当て**: 写真つきレコードを1件出し、銘柄を4択で当てる
- **逆引き**: 銘柄を1つ出し、写真つきレコード4件から該当者を選ぶ
- **誤答の作り方**: 正解と同カテゴリから優先的に3つ選ぶ。足りなければ全体から補う。
  これをしないとカテゴリだけ見た消去法で解けてしまう
- **AIの解答**: 出題対象のレコードを学習データから除外して（leave-one-out）推論し、top1 を答えとする。
  除外しないとAIは自分が覚えたレコードを引き当てるだけになり、常に正解してしまう
- **成績表示**: あなた / AI / でたらめ（4択なので25%）の正解率を並べる

## 11. プライバシー・法務

- 写真は端末外に出ない。書き出しはユーザーが明示操作したときだけ
- 他人を登録する画面に本人同意のチェックを置く
- 未成年の顔を登録しない旨を明記
- 初回に「20歳以上ですか」と「喫煙を推奨するものではありません」を表示
- 「顔から銘柄が分かるという科学的根拠はありません」を判定画面にも常設
- 銘柄名は識別のためのテキスト表示のみ。商標であり各社と無関係である旨を明記

## 12. テスト方針

Vitest で `src/lib` の純粋関数のみを対象にする。押さえる性質：

- 同じ顔ベクトルからは必ず同じ結果が出る（決定論）
- 登録0件のとき `infer` の出力が事前分布と完全一致する
- 登録件数が増えると顔の寄与 `w` が単調に増える
- 尤度が登録0件で一様分布になる
- クイズの誤答が同カテゴリから選ばれる
- 読み込み（インポート）で重複レコードが増えない
- `stats.js` の全数値が `source` または `estimated` フラグを持つ

ヘッドレス検証は `window.__app.feedFace({age, gender, descriptor})` でカメラを介さずに行う。
